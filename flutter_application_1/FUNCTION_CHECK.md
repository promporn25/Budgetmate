# ผลตรวจฟังก์ชัน BudgetMate — 8 กันยายน 2026

## ทดสอบจริงบน iPhone Simulator + Firebase `default`

- ล็อกอินด้วยบัญชีเดิมและกู้คืน session หลัง Flutter hot restart สำเร็จ
- รายรับทดสอบ 1 บาทบันทึกและโหลดกลับได้ (ทดสอบก่อนรอบนี้)
- สร้างเป้าหมายชื่อ `ทดสอบเงินออม 1 บาท` สำเร็จ
- เติมยอดออม 1 บาทสำเร็จ: เป้าหมาย 100%, รายรับ 1, รายจ่าย 1, ยอดคงเหลือ 0 บาท
- หลัง hot restart เป้าหมายและยอดสรุปยังตรงกัน
- หน้ากระเป๋าแสดง 0 เป้าหมายที่กำลังดำเนินการ หลังเป้าหมายทดสอบสำเร็จ
- ข้อมูลทดสอบยังอยู่ในบัญชี ไม่ได้ลบทิ้ง

## แก้ไขจากการตรวจ

- Refresh โหลดข้อมูลผ่านบริการฐานข้อมูลแทนการหน่วงเวลาเฉย ๆ
- เรียงรายการตามวันที่จริง แม้เพิ่มข้อมูลย้อนหลัง
- เปลี่ยนโปรไฟล์ในหน่วยความจำหลังบันทึกสำเร็จ และแสดงข้อผิดพลาดใน dialog
- รูปโปรไฟล์ต้องบันทึก Firebase สำเร็จก่อนอัปเดต UI; รูปใหญ่เกินไปแจ้งข้อผิดพลาด
- เก็บรายการเดิมไว้เมื่อปัดลบแล้วฐานข้อมูลปฏิเสธ พร้อมแสดงข้อความ
- ตรวจจำนวนเงินที่ไม่ถูกต้องและตั้งสถานะเป้าหมายที่มียอดครบตั้งแต่สร้าง
- การเพิ่มยอดออมแบบเดิมไม่เปลี่ยน state ก่อนบันทึกสำเร็จ
- ปฏิเสธการเติมเงินเกินเป้าหมายที่สำเร็จแล้ว
- นับเฉพาะเป้าหมายที่ยังดำเนินการในหน้ากระเป๋า
- แยกโฟลเดอร์ build ออกจาก static analysis

## ชุดทดสอบอัตโนมัติ

`test/data_service_test.dart` ใช้ฐานข้อมูลในหน่วยความจำ ทดสอบยอดรวมรายวัน/เดือน/ปี,
จำนวนเงินผิดรูปแบบ, การเรียงวันที่, การบันทึก/แก้ไข/ลบล้มเหลว, โปรไฟล์,
การลบรูปผิดพลาด, refresh และตัวกรอง user_id, หมวดหมู่กำหนดเอง, สถานะเป้าหมาย,
และการโอนเข้าเป้าหมาย รวม 11 กรณี

ฐานข้อมูลจำลองไม่ยืนยัน Security Rules, การทำงานพร้อมกันหลายเครื่อง หรือ network behavior
ของ Firebase SDK และการตรวจหน้าจอครั้งนี้เป็น debug build ไม่ใช่ release build

## ข้อจำกัดที่ยังต้องทดสอบ/พัฒนาต่อ

- สมัครสมาชิก, Google login, อีเมลรีเซ็ตรหัสผ่าน และเปลี่ยนรหัสผ่าน: ตรวจโค้ดเชื่อม Firebase Auth
  แต่ยังไม่ได้ทำธุรกรรมเหล่านี้จริงในรอบนี้
- เลือกรูปจากกล้อง/คลังภาพ และภาษา/ธีม: ตรวจเส้นทางโค้ด แต่ยังไม่ได้ทดสอบอุปกรณ์จริง
- ลบ/แก้ไขรายการและข้อมูลข้ามบัญชี: ตรวจระดับ service ด้วยฐานข้อมูลจำลอง
  ยังไม่ได้ทดสอบ Firebase จริงด้วยสองบัญชี
- อัตราแลกเปลี่ยนหน้า Home เป็นค่าคงที่ 31.55/31.75 ไม่ใช่ข้อมูลสด
- สลิปใช้ receipt_path ของไฟล์ในเครื่อง ยังไม่ได้อัปโหลดไฟล์ข้ามอุปกรณ์
- หมวดหมู่เก่าใน root categories ไม่มีเจ้าของที่เชื่อถือได้ จึงไม่ได้ย้ายอัตโนมัติ
- ตรวจยอดคงเหลือก่อนโอนอยู่ฝั่งแอป: ยังไม่ป้องกันยอดเกินเมื่อสั่งพร้อมกันหลายเครื่อง
- การวิเคราะห์โค้ดไม่พบ error แต่ยังมี warnings เรื่อง dynamic IconData ในสองโมเดล
  และ lint/info เดิม เช่น withOpacity ที่ deprecated

## Language Setup (ตรวจเพิ่มเติม)

แก้ให้โหลดค่าจากโปรไฟล์/ค่าเริ่มต้น, แสดงภาษาที่เลือกเป็น preview โดยยังไม่เขียน Firebase,
บันทึกโปรไฟล์และค่าเริ่มต้นเมื่อกดถัดไป และแสดง error พร้อมคืนปุ่มเมื่อบันทึกผิดพลาด
เพิ่ม widget/service tests 4 กรณีใน `test/language_setup_test.dart` รวมทั้งหมด 15 กรณีผ่าน
การทดสอบนี้ใช้ฐานข้อมูลจำลอง ไม่ได้สมัครบัญชีใหม่เพื่อเข้าหน้า setup บน Firebase จริง
การเลือกสกุลเงินบันทึกค่าความชอบเท่านั้น หลายหน้าของแอปยังใช้สัญลักษณ์บาทตายตัว


## การปรับตามคำขอล่าสุด: เก็บสกุลเงินต่อรายการ

ยกเลิกการแปลงยอดตามอัตราแลกเปลี่ยน รายการและเป้าหมายใหม่บันทึก `currency`
พร้อมจำนวนเดิม เปลี่ยนค่าเริ่มต้นได้ที่เมนูสกุลเงิน ยอดรวม ประวัติ และเป้าหมาย
กรองตามสกุลที่เลือกเพื่อไม่รวมจำนวนเงินต่างหน่วย ข้อมูลเก่าที่ไม่มี currency
ใช้ ledger_currency ของโปรไฟล์เป็นหน่วยเดิม
ทดสอบรวม 16 กรณีผ่าน ไม่พบ static analysis errors (ยังมี warnings เดิม)
นัมแพดรายรับรายจ่ายใช้หมวดหมู่แบบกระชับขณะเปิดแป้น และมีพื้นที่เลื่อนแยกด้านบน
ตรวจใน iPhone Simulator แล้วเห็นหมวดหมู่สองแถวเต็มและไม่ซ้อนกับแป้น

# BudgetMate: การบันทึกรายรับรายจ่าย

เอกสารประกอบการนำเสนอ พร้อมตัวอย่างซอร์สโค้ดและบทพูด

ตัวอย่างคัดจากโค้ดในโปรเจกต์ ณ วันที่ 12 ตุลาคม 2026 เป็นบางส่วนของคลาส จึงต้องใช้งานร่วมกับโค้ดเดิม ไม่สามารถนำแต่ละตัวอย่างไปรันแยกได้

## สไลด์ 1 — ภาพรวมการทำงาน

หน้าบันทึกรายรับรายจ่ายช่วยให้ผู้ใช้กรอกจำนวนเงิน เลือกหมวดหมู่ และเพิ่มหมายเหตุ โดยสามารถเพิ่มหลายรายการไว้ตรวจสอบ แก้ไข หรือลบก่อนยืนยันบันทึก

**ลำดับการทำงาน:** กรอกข้อมูล → ตรวจสอบข้อมูล → เพิ่มรายการรอบันทึก → ยืนยันบันทึก → แสดงหน้ารายการรายรับรายจ่าย

**ภาพประกอบที่แนะนำ:** ภาพหน้ากรอกข้อมูลและรายการรอบันทึกของแอป

**บทพูด**

> “ส่วนนี้เป็นฟังก์ชันหลักของ BudgetMate ผู้ใช้สามารถบันทึกรายรับและรายจ่าย โดยกรอกจำนวนเงิน เลือกหมวดหมู่ และระบุหมายเหตุได้ ระบบรองรับการเพิ่มหลายรายการไว้ตรวจสอบก่อนกดยืนยันบันทึก”

## สไลด์ 2 — ตรวจสอบข้อมูลก่อนเพิ่มรายการ

จากฟังก์ชัน `_addOrUpdate()` ใน [add_income_expense_screen.dart](../flutter_application_1/lib/screens/add_income_expense_screen.dart)

```dart
final amount = double.tryParse(_amountText) ?? 0;

final service = context.read<DataService>();
if (amount <= 0) {
  ScaffoldMessenger.of(context)
      .showSnackBar(SnackBar(content: Text(service.t('enter_amount'))));
  return;
}
if (_selectedCategory == null) {
  ScaffoldMessenger.of(context)
      .showSnackBar(SnackBar(content: Text(service.t('select_category'))));
  return;
}
```

**จุดที่อธิบาย**

- `double.tryParse()` แปลงข้อความเป็นตัวเลข หากแปลงไม่ได้จะใช้ค่า 0
- ตรวจสอบว่าจำนวนเงินมากกว่า 0 และผู้ใช้เลือกหมวดหมู่แล้ว
- `SnackBar` แสดงข้อความแจ้งเตือน ส่วน `return` หยุดขั้นตอนเมื่อข้อมูลไม่ผ่าน
- `service.t()` ดึงข้อความตามภาษาที่ใช้งาน

**บทพูด**

> “ก่อนเพิ่มรายการ ระบบจะแปลงจำนวนเงินที่กรอกเป็นตัวเลข และตรวจสอบว่าจำนวนเงินมากกว่า 0 รวมถึงเลือกหมวดหมู่แล้ว หากข้อมูลไม่ครบ ระบบจะแสดงข้อความแจ้งเตือนเพื่อให้ผู้ใช้แก้ไขก่อนดำเนินการต่อ”

## สไลด์ 3 — เพิ่มรายการรอบันทึก

ส่วนเพิ่มรายการใหม่ภายใน `setState()` ของ `_addOrUpdate()`

```dart
_tempTransactions.add({
  'amount': amount,
  'category': _selectedCategory!,
  'note': _noteCtrl.text.isEmpty ? null : _noteCtrl.text,
  'id': DateTime.now().millisecondsSinceEpoch.toString(),
});
```

**จุดที่อธิบาย**

- `_tempTransactions` เก็บรายการชั่วคราวที่ยังรอการยืนยันบันทึก
- แต่ละรายการประกอบด้วยจำนวนเงิน หมวดหมู่ หมายเหตุ และรหัสสำหรับจัดการรายการชั่วคราว
- หากไม่กรอกหมายเหตุจะเก็บเป็น `null`
- โค้ดรอบส่วนนี้ใช้ `setState()` เพื่อให้หน้าจอแสดงข้อมูลที่เปลี่ยนไป

**บทพูด**

> “เมื่อข้อมูลผ่านการตรวจสอบ ระบบจะเพิ่มรายการลงในรายการรอบันทึกก่อน ผู้ใช้จึงสามารถเพิ่มหลายรายการ ตรวจสอบยอดเงิน และแก้ไขหรือลบรายการก่อนยืนยันได้ ขั้นตอนนี้ยังไม่ได้บันทึกลงฐานข้อมูล”

## สไลด์ 4 — ส่งข้อมูลไปบันทึก

ส่วนเรียกบันทึกแต่ละรายการในลูปของฟังก์ชัน `_save()`

```dart
final error = await service.addTransaction(
  type: tx['category'].type,
  amount: tx['amount'],
  category: tx['category'],
  date: DateTime.now(),
  note: tx['note'],
);
```

**จุดที่อธิบาย**

- `_save()` วนบันทึกรายการรอบันทึกทีละรายการ
- `type` อ้างอิงประเภทรายรับหรือรายจ่ายจากหมวดหมู่ของรายการ
- `DateTime.now()` ใช้วันเวลาขณะบันทึก
- `await` รอผลการบันทึกก่อนดำเนินการต่อ
- `addTransaction()` คืน `null` เมื่อสำเร็จ หรือข้อความข้อผิดพลาดเมื่อไม่สำเร็จ

**บทพูด**

> “เมื่อผู้ใช้กดยืนยัน ระบบจะส่งแต่ละรายการไปยัง DataService โดยส่งประเภท จำนวนเงิน หมวดหมู่ วันเวลาที่บันทึก และหมายเหตุ จากนั้นรอผลการบันทึกเพื่อตรวจสอบว่าสำเร็จหรือเกิดข้อผิดพลาด”

## สไลด์ 5 — บันทึกสำเร็จและอัปเดตหน้าจอ

ส่วนท้ายของ `_save()` หลังบันทึกครบทุกรายการ

```dart
if (!mounted) return;
showSuccessNotice(context, 'transaction_saved');
_tempTransactions.clear();
_editingId = null;
_selectedCategory = null;

Navigator.pushReplacement(
    context, noAnimationRoute(const IncomeExpenseScreen()));
```

**จุดที่อธิบาย**

- `mounted` ตรวจสอบว่าหน้าจอยังอยู่ก่อนใช้งาน `context`
- แจ้งว่าบันทึกสำเร็จ และล้างรายการชั่วคราว
- เปิดหน้า `IncomeExpenseScreen` แทนหน้าบันทึกเดิม

**บทพูด**

> “เมื่อบันทึกครบทุกรายการ ระบบจะแสดงข้อความแจ้งสำเร็จ ล้างรายการรอบันทึก และเปิดหน้ารายการรายรับรายจ่ายเพื่อให้ผู้ใช้ตรวจสอบข้อมูลที่บันทึกแล้ว”

## ข้อมูลเสริมสำหรับตอบคำถาม

**หน้าจอกับส่วนจัดการข้อมูลแบ่งหน้าที่กันอย่างไร?**

หน้าจอรับข้อมูลและแสดงผล ส่วน `DataService.addTransaction()` ตรวจสอบผู้ใช้และจำนวนเงิน สร้างข้อมูลรายการ แล้วเรียกส่วนฐานข้อมูลเพื่อบันทึก เมื่อสำเร็จจึงเพิ่มรายการในหน่วยความจำและเรียก `notifyListeners()` ให้ส่วนที่ติดตามข้อมูลอัปเดต

อ้างอิง: [data_service.dart](../flutter_application_1/lib/services/data_service.dart)

**ป้องกันการกดบันทึกซ้ำอย่างไร?**

ฟังก์ชัน `_save()` ตรวจสอบ `_saving` ก่อนเริ่ม หากกำลังบันทึกอยู่จะหยุดการเรียกซ้ำ และใช้ `finally` คืนสถานะเมื่อทำงานเสร็จหากหน้าจอยังอยู่

**ถ้าบันทึกบางรายการไม่สำเร็จจะเกิดอะไรขึ้น?**

รายการถูกบันทึกทีละรายการ จึงอาจสำเร็จบางรายการก่อนเกิดข้อผิดพลาด เมื่อ `addTransaction()` คืนข้อความข้อผิดพลาด หน้าจอจะนำรายการที่บันทึกสำเร็จแล้วออกจากรายการรอบันทึก เก็บรายการที่เหลือไว้ และแสดงข้อความผิดพลาด

**รหัสรายการชั่วคราวกับรหัสในฐานข้อมูลเหมือนกันหรือไม่?**

รหัสใน `_tempTransactions` ใช้จัดการรายการบนหน้าจอ ส่วน `DataService.addTransaction()` สร้างรหัสใหม่ด้วย UUID สำหรับรายการที่บันทึกจริง

## หากมีเวลานำเสนอน้อย

ใช้สไลด์ภาพรวม 1 หน้า และสไลด์โค้ด 1 หน้า โดยเลือกตัวอย่าง “ตรวจสอบข้อมูล” กับ “ส่งข้อมูลไปบันทึก” วางคู่กับภาพหน้าจอจริง แล้วอธิบายลำดับตั้งแต่กรอกข้อมูลจนถึงบันทึกสำเร็จ
